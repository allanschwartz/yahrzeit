PHP Internal Map

Standalone developer documentation audited against the current source files, functions, constants, includes, and call paths. It records observed behavior only; where the code does not establish an answer, it says unclear.

Overview and architectural boundaries

Project style: this is intentionally a procedural PHP application. Preserve its procedural module boundaries and table-based rendering assumptions; this map does not recommend a class conversion.

Observed control path

cron → bin/yahrzeit_scheduler → bin/yahrzeit → bin/yahrzeit_engine.php → include/yahrzeit_policy.inc.php → command stream → nc → Arduino controller. Cron supplies the policy-derived time, the scheduler decides whether a phase applies, the wrapper selects and transports an operation, the engine walks the memorial records, and the policy module decides which records are active.

Schedule-maintenance path: 7minhag.php → /usr/local/sbin/yahrzeit-fix-crontab → bin/fix-up-crontab → user crontab. The same repository helper is called by the scheduler's cron-refresh phase for moving sunset times.

Controller boundary: controller interaction is confined to a small number of well-defined paths.

  • 1yizkor.php is the only web screen that can initiate an immediate controller operation.
  • bin/yahrzeit_scheduler initiates automatic operations.
  • bin/yahrzeit is the only component that transmits commands over the network.
  • bin/yahrzeit_engine.php, include/yahrzeit_policy.inc.php, and include/leds.inc.php decide or generate command text but do not transmit it.
  • names.inc.php owns parsing and writing the memorial CSV.
  • panels.inc.php owns static panel geometry.
  • date_support.inc.php owns Gregorian/Hebrew date, sunset, and Shabbat helpers.
  • leds.inc.php owns the mapping from panel IDs/person locations to controller command text. It does not transmit.
  • index.php only redirects to 0yahrzeit.php. The eight files under help/ render documentation through misc.inc.php; only Home Help and Minhag Help read minhag.ini. None writes data or contacts the controller.
  • Top-level screen files primarily render legacy table-based pages and handle their GET/POST flows.

Command wrapper and transport

bin/yahrzeit
Kind / purpose
Bash execution and transport stage used by the scheduler and web screens. It selects an operational mode, invokes the PHP engine as needed, prints non-transmitting streams, or transports streams to the Arduino controller.
Major functions
set_mode, find_yahrzeit_php, run_yahrzeitd, emit_commands, slowcat, select_nc_quit_option, log_controller_failure_results, transmit_commands, and run_logged_operation.
Constants / global state
Shell variables including CONTROLLER_HOST and CONTROLLER_PORT sourced from bin/yahrzeit-controller.conf; transport timing defaults; MODE, TRANSMIT, REPORT_KIND, and REPORT_DATE.
Direct dependencies
bin/yahrzeit_engine.php for normal/audit/report paths; PHP with Calendar extension; nc and a timeout command for transmission.
Observed callers
1yizkor.php, 6reports.php, bin/yahrzeit_scheduler, cron/manual operators.
Data I/O
Sources bin/yahrzeit-controller.conf for the controller connection. Engine modes read project data through PHP modules. The wrapper has no project data write path.
Controller boundary
Yes by default. --dry-run prints instead. Audit/report modes force non-transmission.
Role boundary
Owns the only observed TCP/nc transport path and the hard-coded Yizkor/all-on/all-off streams. In scheduler summary mode it validates response counts and reports timeout, transport, controller rejection, empty-response, and incomplete-response failures. Calendar and per-person lighting rules remain outside it.

Memorial database

data/yahrzeits-rev4.csv
Kind / purpose
Eight-column Rev4 CSV record store for names, English and Hebrew dates, option tokens, historical location, and active panel/column/row location. Additional trailing columns may exist and are preserved by the single-record editor.
Readers
names.inc.php, the Single Name editor, Reports download/upload validation, and all callers that load mapped memorial records through yahrzeit_readDB().
Writers
Single Name atomically replaces one mapped record after making an edit backup. Reports upload replaces the entire file after making an upload backup. The installer preserves the appliance copy across repository updates. yahrzeit_writeDB() can rewrite the file but has no current source-tree caller.
Controller boundary
Contains memorial facts and locations only. Policy and engine code turn those records into decisions and commands.

Derived runtime artifacts

data/backups/ contains timestamped edit/upload backups. data/automation.log receives cron-redirected scheduler and wrapper output and is rotated weekly by installer-created logrotate configuration. The user's crontab, /etc/yahrzeit-cron-user, and the installer's Apache/systemd/sudo/logrotate files are operational state outside these three authoritative project files.
